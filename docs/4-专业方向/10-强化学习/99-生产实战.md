## 🏭 一个真实项目从 0 到 1

### 先看版图：RL 到底用在哪儿

```mermaid
pie showData

    "推荐/广告中的部分决策场景" : 30
    "LLM 对齐（RLHF）" : 25
    "游戏 AI" : 20
    "机器人控制" : 15
    "其他（能源调度、算力调度等）" : 10
```

**如实讲：纯 RL 的生产项目很少。** 原因就是上一页的三座大山——奖励难设计（定歪一分跑偏十里）、样本贵（真实系统上试错一次可能就是真金白银的损失）、不稳定（换个种子结果两样）。所以真实落地的 RL 几乎都戴着"护具"，演化出三种典型姿势：

1. **先仿真后真实**：机器人、自动驾驶在仿真器里摔个千百次，学好了再上真机微调；
2. **离线强化学习（Offline RL）**：从海量历史决策日志里学策略，全程不在线试错——推荐、风控这类"日志大户"的主流选择；
3. **RLHF**：让奖励模型代替真人打分，把"学人类偏好"变成一个可规模化的 RL 问题（详见[微调与对齐](../07-自然语言处理与LLM/05-微调与对齐.md)）。

三种姿势一张表看懂差别：

| | 仿真 RL | 离线 RL | RLHF |
|--|---------|---------|------|
| 数据从哪来 | 仿真器里自己造 | 历史决策日志 | 人类偏好 + 奖励模型 |
| 试错成本 | 零（摔的是仿真器） | 零（只回看历史） | 低（模型生成，人工标注贵） |
| 典型场景 | 机器人、游戏、布局决策 | 推荐、风控、客服策略 | 对话、文案、大模型对齐 |
| 最大风险 | 仿真到现实有 gap | 学不到日志外的好动作 | 奖励模型被钻空子 |

### 假想项目：智能客服的对话策略

以一个贴近现实的项目走一遍全流程：客服机器人在每次用户提问后，要从「直接回答 / 追问澄清 / 推荐商品 / 转人工」四个动作里挑一个，目标是提升**一次对话解决率**、同时压住转人工成本。

```mermaid
graph TD
    A["需求定义<br/>指标与奖励函数 v1"] --> B["历史日志整理<br/>离线 RL 训练"]
    B --> C["离线评估<br/>策略评估/回放"]
    C --> D["仿真回放<br/>用户模拟器压测"]
    D --> E["小流量在线 AB<br/>护栏兜底"]
    E --> F["监控迭代<br/>盯指标与钻空子行为"]
    F -->|奖励函数 v2、v3 ……| A
```

分阶段拆解（每个阶段说清"做什么、花多久、常见卡点"）：

- **需求定义**：与业务方对齐目标——不是"答得快"而是"一次解决"。把目标翻译成奖励函数：会话结束时用户点"已解决" +10、超时或投诉 −20、转人工 −5（占线成本）。**奖励设计会反复迭代 4~5 版，是整个项目的主线，占掉近一半时间**。
- **数据**：全部来自历史对话日志（哪家公司都不缺客服日志）。清洗、脱敏、把每通对话切成 (状态=对话上下文与用户情绪, 动作=机器人响应类型, 奖励=会话结局打分) 三元组——离线 RL 的口粮。
- **设备与算力**：策略模型不大（百万~千万参数级），单张云端 GPU 足够；大头开销其实在日志管道与仿真评估的工程上，而不是算力。
- **算法选型**：离线 RL 起步（如保守 Q 学习一类，宁可信日志里的，不瞎猜没见过的），而不是上来就在线 DQN——真实用户不是练功靶子。基线必须有两个：现有规则策略、监督学习策略；打不过基线的 RL 没有上线资格。
- **训练炼丹**：一轮 = 改一版奖励 → 离线训练 → 离线评估看曲线。玄学时刻：指标上去了，抽样看 case 却发现策略学会了"早点转人工甩锅"。
- **评估**：离线策略评估（用日志估计新策略的回报）+ 用户模拟器回放；在线阶段用 AB 实验，实验组用新策略、对照组用旧策略，盯一次解决率、转人工率、会话时长。
- **部署**：小流量灰度（比如 5% 用户），配硬护栏——连续两轮用户明确不满就强制转人工；策略模型走常规在线推理服务。
- **监控与迭代**：盯一次解决率（涨没涨）、转人工率（有没有甩锅）、投诉率（护栏指标）；用户问题分布漂移后要重训，周期通常按季度。

<details>
<summary>📋 展开一个真实的迭代故事：奖励作弊现场</summary>

第一版奖励上线后，一次解决率 +3.2%，团队正要庆祝，转人工率报表拉出来：+18%。抽 case 发现：新策略学会了**把难缠用户在第二轮就转出去**——剩下的"简单会话"解决率自然高，指标涨了，问题没解决，还把人工坐席打爆了。

修复过程基本就是奖励函数的迭代史：v2 给"转人工"加固定罚分 → 机器人又学会了死不转人工，投诉率上升；v3 改成"按用户情绪判断该转没转"的软罚分，并给"投诉 −50" 加权；v4 引入"24 小时内重复进线 −15"（治标更治本）。四版之后指标才同时转正。

教训：**奖励函数是 RL 项目的"法律条文"——条文有漏洞，智能体一定是最积极的钻空子者。**

整个演进节奏整理成表（每版间隔约两周，评审标准只有一个问题："如果我是智能体，这条规则怎么钻空子拿高分？"）：

| 版本 | 奖励设计 | 结果 | 诊断 |
|------|----------|------|------|
| v1 | 会话解决 +10 | 一次解决率 +3.2%，但转人工率 +18% | 转人工没有成本项，学会了甩锅 |
| v2 | v1 + 转人工固定罚分 | 死不转人工，投诉率上升 | 罚分一刀切，没区分该转与甩锅 |
| v3 | 罚分按用户情绪软判 + 投诉重罚 | 指标好转，会话时长暴涨 | 长会话里反复试探，缺时间成本 |
| v4 | v3 + 每轮小罚 + 重复进线罚 | 解决率 +4.1%，转人工率持平 | 收工，转入季度重训节奏 |

</details>

## 🎁 奖励设计坑体系化：三类病、三种药

上一页说过"奖励设计占掉项目近一半时间"，这里把踩过的坑整理成三类，**先分清得的是哪种病，再对症下药**：

| 病类 | 典型症状 | 真实案例 | 修法 |
|------|----------|----------|------|
| **稀疏奖励**（Sparse Reward） | 训练曲线长期躺平；Q 表/价值网络大片区域始终是 0，"信息流不过去" | 机器人叠毛巾只有"叠好 +1"，中间全是 0——它永远等不到第一个正反馈 | 奖励塑形（给中间状态发"进度分"，如离目标越近分越高）；课程学习（先学 1 步任务再逐步加长）；内在好奇心奖励（没见过的状态自发给分） |
| **奖励误设**（Misspecified Reward） | 代理指标涨了、业务没变好；离线指标与线上体感脱节 | 客服追"会话变短"，学会用一句话把用户噎到沉默关闭会话 | 目标拆解为多目标加权（时长 × 解决率 × 投诉）；上线前人工抽 case 对照"业务真目标"；指标事前注册，防止事后挑好看的 |
| **奖励作弊**（Reward Hacking） | 分数奇高但行为荒谬；越训越"聪明"地钻空子 | 清洁机器人把障碍物推到传感器盲区；游戏智能体在原地打转反复吃刷新的奖励 | 封漏洞（把已知钻法写成负奖励/约束）；奖励模型配对抗评估与人工评审；对齐场景加 KL 约束拴住策略（见[微调与对齐](../07-自然语言处理与LLM/05-微调与对齐.md)） |

三类病的判别顺序：曲线不动 → 先查**稀疏**；曲线漂亮但业务没变化 → 查**误设**；分数高得离谱、行为荒诞 → 基本是**作弊**。共同的后手都是一样的：小流量灰度 + 人工抽 case + 护栏指标兜底。

评审任何一版奖励函数时，把下面五个问题依次过一遍（多个团队的共性教训，经验参考）：

- 如果我是**最贪心的智能体**，这条规则最快的刷分路线是什么？（把上面案例里的"甩锅""死不转人工"都想一遍）
- 有没有"**不完成任务也能拿分**"的漏洞——静坐不动、提前退出、把目标挪走？
- 每一项奖惩的**时间尺度**对不对——秒级动作配上了天级结算，信号根本传不回去？
- 护栏指标（成本、投诉、安全）有没有对应的**负奖励或硬约束**，还是只活在监控报表里？
- 这版改动能不能用日志**离线回放验证**——验证不了的就先别上线？

## 🌉 仿真到现实 gap：三张面孔与各自缓解

"先仿真后真实"路线最大的坑：仿真里满分毕业，真机上第一秒翻车。仿真器再精细，也模拟不了全部现实——这个 gap 拆开看有三张面孔，缓解手段各不相同：

| gap 类型 | 缺的是什么 | 典型症状 | 缓解手段 |
|----------|-----------|----------|----------|
| **物理 gap** | 摩擦、延迟、回差、电机噪声等物理细节 | 仿真里动作干净利落，真机上抓不住、打滑、抖动 | 域随机化（训练时故意把摩擦系数、噪声幅度随机化，逼策略学出鲁棒性）；系统辨识（用真机数据校准仿真参数）；真机微调（仿真给底子，真机小步精调） |
| **感知 gap** | 仿真渲染的图像与真实摄像头/传感器的域差 | 仿真里认得的物体，真机摄像头一拍就"不认识" | 在渲染里加噪声/光照/遮挡随机化；用真实图像做域适应或预训练表征；关键感知模块干脆用真实数据单独训练 |
| **任务分布 gap** | 仿真里的任务集合 ≠ 部署时真实遇到的分布 | 训练时的 100 种摆放全学会，现实第 101 种就傻眼 | 任务课程化（从易到难自动扩展）；自动生成贴近失败的难任务（对抗式任务生成）；部署端持续采集失败 case 回流训练 |

通用的兜底三件套：**域随机化**（让策略见过足够多的"世界版本"）、**保守动作约束**（真机上限制每次动作幅度，出错可接管）、**真机微调**（仿真打底、真机收尾）。机器人团队之间的老玩笑：**仿真一分，真机一年**——说的就是三张面孔加起来的总账。

## 🗄️ 离线 RL 的数据质量红线

离线 RL 看着最安全（只回看历史、不在线试错），但它有自己的命门：**Q 网络会对"日志里从没做过的动作"外推出虚高估值**——训练时没人能揭穿它（没有反馈），上线一执行就现原形（分布偏移，Distribution Shift）。所以数据侧有几条不成文的红线，动工前先逐条检查：

- **红线一：动作覆盖度**。日志里的动作分布必须覆盖"新策略可能想选的动作"。离散动作看每个关键 (状态簇, 动作) 的出现次数；连续动作看行为策略的多样性（熵）。日志是单一死板策略产的 → 新策略几乎必然跳出覆盖圈，此时离线 RL 形同裸奔。
- **红线二：多策略拼接的混杂**。历史日志往往来自 N 个版本的策略（规则 v1、模型 v2、人工运营混合……），数据是"混合人格"产的。必须按策略版本打标、分层评估，否则"谁的效果"都说不清——这是观察数据的老问题（混淆，见[第 11 章](../11-因果推断/01-相关不等于因果.md)）在 RL 里的翻版。
- **红线三：幸存者偏差**。只记"成功会话/未流失用户"的日志，会让智能体以为错误动作从没发生过（它们被日志开除了）。确认失败样本、中断轨迹都被完整落盘。
- **红线四：序列完整性**。RL 靠 (s, a, r, s') 链条学习，时间戳错乱、状态快照缺失的日志对 RL 是毒药（监督学习还能凑合，RL 直接学歪）。
- **红线五：数据量级**。离线 RL 吃数据远比监督学习凶——经验上千万级转移量级起步才有讨论价值（经验参考，随任务难度浮动）。

过了红线之后的标配保险：**保守类算法**（如保守 Q 学习 CQL：给分布外动作的 Q 值上惩罚，压住虚高）；**行为克隆正则**（新策略别离日志策略太远）；**离线策略评估**（FQE、重要性采样等，先用日志估计新策略回报再谈上线）；上线后**只保守执行 + 硬护栏**，绝不放开探索。

<details>
<summary>🧮 展开看：离线策略评估（OPE）三件套——上线前的"沙盘推演"</summary>

离线 RL 最要命的一问："新策略到底值多少分？"——不能上线跑，就只能用日志推演。三条主流路数，成本递增、可靠性也递增：

| 方法 | 一句话原理 | 软肋 |
|------|-----------|------|
| 重要性采样（IS） | 用"新策略给这条轨迹的概率 ÷ 日志策略给的概率"作权重，给历史回报重新加权 | 比值逐 step 连乘后方差爆炸，长序列基本不可用 |
| 值函数估计（FQE） | 学一个"新策略下的价值函数"，直接给状态/动作打分推总分 | 还是外推——学错了没人能揭穿 |
| 模拟器回放 | 训一个环境模型（对话场景常用 LLM 扮演用户），让新策略在里面真跑 | 环境模型不准，结论跟着歪 |

工程惯例是三件套**交叉验证**：三种方法给出的估值方向一致、量级接近，才有底气进小流量；若分歧巨大——那本身就是"数据覆盖不足"的警报，先回查红线一，而不是挑一个最好看的数字。

</details>

## 🧭 场景选型表

| 你的场景 | 推荐路线 | 理由 | 不推荐 |
|----------|----------|------|--------|
| 环境可完整仿真（游戏、机器人、页面布局） | 仿真 RL | 试错零成本，随便摔 | 一上来真机在线试错 |
| 有大量历史决策日志（推荐、风控、客服） | 离线 RL | 不在线试错，日志就是教材 | 直接在线探索 |
| 有清晰、可自动化的人类偏好信号（文案、对话） | RLHF 路线（奖励模型 + PPO 类） | 奖励可以被"学"出来 | 手写规则奖励硬训 |
| 状态小且离散（几千格以内） | 表格 Q-Learning | 简单稳定可解释 | 上神经网络（杀鸡用牛刀） |
| 一次决策、不涉及长期后果 | 监督学习 / 规则 | 没有"动作影响未来"就不是 RL 问题 | 为了时髦硬上 RL |

## 🧾 立项自检清单：这个项目该不该上 RL

下单前逐条打勾，缺两条以上建议回到监督学习或规则：

- [ ] 决策是**序列**的：这一步会影响后面的局面（只做单次判断的不算）
- [ ] 奖励能写成数字，且业务方认可"这个数字高 = 真的好"
- [ ] 有便宜的试错场：能仿真，或有海量日志可离线学
- [ ] 存在可对齐的护栏指标，钻空子行为能被及时看见
- [ ] 有两个能打的基线（规则 / 监督学习），并接受"打不过就撤"
- [ ] 团队接受训练不稳定、迭代以"版"计（而不是以天计）

## 💣 踩坑实录

- **坑 1：奖励作弊（Reward Hacking）**：智能体钻奖励函数的空子刷分——客服学会甩锅转人工、清洁机器人学会把障碍物推到传感器看不见的角落。→ 病理与三类病的判别法见上方「奖励设计坑体系化」；解法没有银弹：小流量灰度 + 人工抽 case + 护栏指标（成本、投诉率）+ 奖励函数版本化管理。
- **坑 2：仿真到现实 gap**：仿真里策略满分，真机秒翻车。→ 三张面孔（物理/感知/任务分布）分别对症，见上方专节；预算永远预留真机微调的工期。
- **坑 3：在线试错的成本与安全**：在真实系统上探索 = 拿真实用户和真实钱试错，一次坏策略可能就是一次舆情。→ 探索动作白名单化、动作幅度限幅、异常熔断回退旧策略；金融医疗类场景干脆只做离线 RL（先过上方数据红线）。
- **坑 4：离线 RL "学了就敢上线"**：离线训练指标好看 ≠ 在线表现好——分布外动作的估值是纸面富贵。→ 红线五查 + 保守算法 + 离线策略评估三保险，缺一不上。
